# DOOM: SOVEREIGN

A Doctor Doom mod for Minecraft Java **26.1.2** (Fabric, GeckoLib), developed in a session that had **no
access to the Fabric, Mojang, GeckoLib or JDK 25 download hosts**. Everything here was therefore built and
validated *without Minecraft*. Nothing has been launched or seen in game; see `docs/STATUS_REPORT.md` for
exactly what is validated, what awaits integration, what is only specified, and what is blocked.

| Directory | Contents | Check it |
|---|---|---|
| `core/` | pure-Java game domain (Java 21 syntax, Gson only) — energy, heat, focus, cooldowns, force field, flight, modules, research, Doom Analysis, Doombot AI, security, power network, persistence, presentation catalog | `./gradlew :core:test` (167 tests) |
| `art/` | Python generators for every asset + a preview renderer, validators and tests | `python3 art/build_all.py` (rebuilds everything, 27 tests) |
| `art/previews/` | rendered turnarounds, state sheets, animation contact sheets, HUD mock-ups, spectrograms | open the PNGs |
| `mod/` | the future Fabric module: the generated resource tree (249 files), an unverified `fabric.mod.json` template, the planned package layout | `mod/README.md` |
| `docs/` | skeletons, animation library, audio, HUD, VFX, art direction, asset manifest, performance, integration manifest, status report | start with `docs/STATUS_REPORT.md` |

Requirements: JDK 21 for `core` (JDK 25 once the mod module exists); Python 3 with `numpy`, `Pillow` and
`soundfile` (libsndfile with Vorbis) for `art/`.

Next step: `docs/MINECRAFT_26_1_2_INTEGRATION_MANIFEST.md`, step 1.

All art and audio are original and procedurally generated by the code in `art/`; no third-party, ripped or
sampled material and no voice or likeness imitation is used.
